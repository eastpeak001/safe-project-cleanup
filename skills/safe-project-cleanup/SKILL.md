# 工程空间管家

Windows side。减少空间占用，同时保留工程开发、运行和恢复能力。一次安装供多个工程使用；每个工程的保护规则、身份、稳定性证据和授权独立核对。

## 入口和权限

- 默认只读盘点及计划。当前工程调用以已确认的工程根目录为范围；用户指定范围优先。更广的开发资源盘点只扫描用户指定或已确认的工程、开发缓存和临时目录，不遍历整盘。
- 先读适用 AGENTS.md 和当前文件。若用户配置了长期记忆，可补充读取相关历史；没有记忆插件也可完整使用。镜像、保留来源和共享管理目录按当前工程规则保护。记忆、技能选中、计划 `approved` 字段、`--apply` 都不能赋予删除权限。
- 执行须有实际用户批准的精确清单，或明确涵盖此次动作的持久工程策略。已经批准的范围不逐项重复询问。永久删除、整个旧版本淘汰和解除冻结分别需要对应授权。脚本不能鉴别人类授权来源，由 Codex 核对真实会话授权再填写批准记录。
- 不配置定时任务，不改全局环境/AGENTS.md，不擅自迁移稳定工具链，不提交推送，不触发硬件或发布。技能发现不保证每次收尾自动运行；持续触发另行授权。

## 盘点与分类

使用 [scripts/cleanup.py](scripts/cleanup.py) 的 `scan`。每次给出时间、条目和深度上限，先找主要占用，再定向深入。先确认独立报告工作目录；所有命令在子命令前显式传入 `--workspace-root <绝对目录>`，`--out` 必须位于该目录内。优先用户指定的非系统盘位置，不假设 D 盘存在。使用唯一的新报告文件，排除安装、报告和测试目录。工作目录禁止作为清理目标。记录覆盖、跳过、失败、截断和未知；续扫指定 `continuation_roots` 中的子目录，不累加重叠扫描的大小。

- A：已证实可重复生成的派生缓存、构建中间产物、完成的验证产物。目录名只是线索；报告中的 `class_hint` 不是资格认定。
- B：依赖目录、包缓存、旧下载、共享资源。核对清单/锁文件、版本、引用、下载可用性、本地改动和离线唯一副本。优先官方清理入口；入口越过批准范围则跳过。不要运行不可信仓库脚本来验证。
- C：旧工程、备份、发布/冻结、模型、数据集、SDK、工具链、重复文件。默认保留，提出具体建议。

保护源码、配置、锁文件、AGENTS.md、未知未跟踪内容、未提交工作、秘密/签名材料、PCB、原始数据、日志/失败证据、生成媒体、唯一 APK/固件/ELF/MAP，以及 Git/共享元数据。保护项即使 ignored 或位于 build 也受保护；明确可重建的纯派生物可按授权处理，不因 untracked 永久保护。目录内有未保留的保护项就拆成精确子项，不整体删除。

核对 Git 状态、嵌套仓库、子模块、worktree；非 Git 工程同样保护。脚本 Git 调用禁可选锁并禁用外部过滤器/监视器；失败视为未知。Codex worktree 用当前提供的管理/归档能力，核对归属、活跃、固定和 ignored 内容。能力或身份不明只报告；聊天归档不代表释放磁盘。

## 旧版本

执行版本审查时读 [references/workflow.md](references/workflow.md) 的版本规则及 [references/version-template.json](references/version-template.json)。显式核对工程、主线、硬件身份，按数字排序。两种模式：

1. `current-and-rollback`：保留当前工作版本和不同的、已验证可用回退版本（如 v4/v3），活跃、冻结、共享依赖等另行保留。
2. `latest-stable-only`：用户明确选择后，仅保留最新稳定版本。最新版未验证或无稳定性证据，只建议，不淘汰。

检查保留版本/其他工程/任务/脚本的引用、独有材料和未提交工作、活动/冻结状态、独立运行能力。列明引用范围和未覆盖处；局部零命中不证明全机无引用。旧实现差异可明确淘汰，重要独有资料先有经核对的保留位置。独立 `.git` 仅在唯一提交、引用、reflog/本地有价值历史已保留后处理；共享元数据不删除。

## 执行与验证

先读 [references/workflow.md](references/workflow.md) 的清单/批准格式和脚本限制，使用 `plan` 生成身份快照，再 `execute` dry-run。拒绝路径逃逸、相似前缀、链接、嵌套候选、盘根/用户根、覆盖保留/安装/报告路径。执行前复核身份及活动证据；变化、新保护项、锁、并发或未知就跳过，不强停、不提权、不盲目重试。禁止 `git clean -fdx`、通配符删除及跨 shell 拼接删除。

归档前核对目标空间，归档后校验内容并排练恢复，之后才按授权处理原件。脚本的 `archive-delete` 需事先有恢复排练证据；对可重建大缓存无需重复完整备份。已证实非独有并明确淘汰的旧工程可永久删除，不强制完整同盘备份。

分别报告候选逻辑大小、处理/删除逻辑大小、保留备份占用、涉及卷的实测可用空间变化。隔离/同盘移动/回收站仍占空间；跨盘搬迁只改变占用分布。硬链接、压缩、稀疏、并发写入影响估算。永久删除不可撤销；备份恢复、重新构建和重新下载不同。

清理前采集保护文件和 Git 基线，清理后核对并执行适合工程的最小、已审核验证；重新生成占用计入结果。保留已有失败，区分新失败；未经真实工程验证，不宣称工程完整性通过。

调用示例、两种版本策略、可选 AGENTS.md 收尾约定见 [references/examples.md](references/examples.md)。持久策略模板见 [references/policy-template.json](references/policy-template.json)，只有用户明确批准后才启用。
